# 09 · 前端与接口契约

> 01–08 篇讲的是引擎、图、记忆、检索、Agent 与门禁；本篇讲的是**这些能力在人机界面上长什么样**：Vue3 工作台的信息架构、每个视图负责什么、路由与状态怎么组织，以及后端 13 个控制器对外暴露的 HTTP/SSE 契约——包括流式写作的四种事件、取消与落库的完整链路、并发去重，以及 JWT + 归属校验构成的权限边界。
>
> 本文所有结论均以当前代码为准，每条关键论断给出 `路径:行号` 证据。

## 1. 本篇范围与总览

MoLan 的对外形态是「一个 Vue3 单页应用 + 一组 REST/SSE 接口」：

```
浏览器 (Vue3 + Element Plus + Pinia)
   │  axios：baseURL = <挂载目录>api，超时 180s，自动挂 Authorization: Bearer <token>
   │  (frontend/src/api/index.ts:28-34, frontend/src/utils/base.ts:18)
   ▼
Spring Boot（context-path = /api，端口 21160）
   │  SecurityFilterChain → AuthFilter（JWT）→ Controller → Service
   │  OwnerAccessInterceptor（命中 novelId/configId/cardId 路径变量时校验资源归属）
   ▼
MySQL / MongoDB / Redis / Milvus（数据面，详见 04、05 篇）
```

两条链路：**普通请求**走 axios，响应统一为 `ApiResponse{code,message,data}`（`backend/src/main/java/com/novel/system/dto/response/ApiResponse.java:13-36`）；**流式请求**用 `fetch` + `ReadableStream` 手写 SSE 解析（`frontend/src/views/NovelDetail.vue:772-876`），不复用 axios。

### 2.4 路由组织与守卫

- **hash 路由**（`createWebHashHistory`）：网关会把服务挂在子路径下，history 模式会丢掉挂载目录（`frontend/src/router/index.ts:1-6`）；路由组件全部懒加载（`:11` 起）。
- 守卫（`router/index.ts:90-138`）：无 token 且非 guest 路由 → `/login`；有 token 且是 guest 路由 → `/novels`；有 token → 调 `authStore.fetchUser()` 校验，**60 秒内不重复校验**（`:88,110-114`），401 则清 token 并带 `redirect` 回登录页。

### 2.5 状态管理

Pinia 三个 store（`frontend/src/stores/`）：

| Store | 职责 |
| --- | --- |
| `authStore` | token 持久化于 `localStorage`、当前用户、`isLoggedIn`/`username`/`role`、登录注册登出、60s 校验缓存（`authStore.ts:6-101`） |
| `configStore` | 模型配置列表与 `activeConfigs`（`configStore.ts:6-71`） |
| `novelStore` | 小说列表、当前小说、章节、角色、伏笔四类集合及其拉取/增删改动作（`novelStore.ts:7-252`） |

视图内的大块局部状态（如流式生成的 `streamingContent` / `streamCheckpoints` / `streamAbortController`）**不进 store**，留在组件内用 `ref` 管理（`NovelDetail.vue:515-521`）。

## 3. 接口契约

### 3.1 通用约定

| 项 | 约定 | 证据 |
| --- | --- | --- |
| 前缀 | 全部接口带 context-path `/api`（可由环境变量覆盖） | `backend/src/main/resources/application.yml:6` |
| 响应包装 | `{code:200, message, data}`；`code != 200` 时前端统一弹错并 reject | `ApiResponse.java:22-36`；`frontend/src/api/index.ts:52-58` |
| 认证头 | `Authorization: Bearer <token>`，JWT 含 `sub/username/role` 三个 claim | `JwtConfig.java:53-65`；`AuthFilter.java:43-46` |
| 分页 | 列表接口支持 `page`（0 起）与 `size`（0 表示不分页），越界自动收敛 | `NovelController.java:60-76`；`ChapterController.java:57-69` |
| 错误语义 | 业务错误在响应体内以 `code` 表达，鉴权错误走 HTTP 401/403 + JSON 体 | `SecurityConfig.java:43-54` |

### 3.2 接口清单（按业务域分组）

## 4. SSE 流式协议

### 4.1 端点与连接方式

| 端点 | 事件源 | 事件类型 |
| --- | --- | --- |
| `POST /api/chapter/stream-write` | `StreamingChapterController.java:86` | `token` / `checkpoint` / `complete` / `error` |
| `POST /api/wizard/novel/{novelId}/arc/{arcIndex}/chapter-outlines/stream` | `WizardController.java:85` | `progress` / `outline` / `complete` / `error` |

两个端点都返回 `text/event-stream`，由 `SseEmitter` 承载，10 分钟超时（`StreamingChapterController.java:100`、`WizardController.java:90`）。
浏览器端不用 `EventSource`（无法带 POST body 与 Authorization 头），而是用 `fetch` + `ReadableStream` 手工解析 `event:` / `data:` 行（`NovelDetail.vue:801-860`、`CreateNovelWizard.vue:607-660`）。公共封装 `frontend/src/utils/sse.ts` 提供带重连的通用 SSE 客户端，但工作台的章节流式走的是页面内手写分支。

### 4.2 事件类型与载荷

| 事件 | 载荷 | 语义 | 前端消费方式 | 证据 |
| --- | --- | --- | --- | --- |
| `token` | 纯文本增量（**不是 JSON**，是正文片段） | 写作节点逐 token 吐字 | 直接追加到 `streamingContent` | `ai/chain/ChapterGenerationChain.java:407-417`；`NovelDetail.vue:843-857` |
| `checkpoint` | JSON 字符串：`{"node":"outline\|writing\|audit_router","action":"APPROVE\|REVISE\|REJECT\|REDIRECT","rationale":"理由"}` | AuthorAgent 在检查点给出的**审批指令** | `JSON.parse` 后 push 进 `streamCheckpoints`，渲染成一排只读徽标 | `ai/graph/NodeExecutor.java:150-164`；`NovelDetail.vue:828-833` |
| `complete` | 空串（若有文本则作为校验摘要） | 图执行结束且正文非空 | 置 `streamingStatus='completed'`，刷新章节/人物/节奏 | `StreamingChapterController.java:174-186`；`NovelDetail.vue:811-816,884-890` |
| `error` | 纯文本原因（重复提交、超时、生成失败原因） | 生成失败或被拒绝 | `ElMessage.error` + 状态置 `error` | `StreamingChapterController.java:92-97,105-112,187-202`；`NovelDetail.vue:819-824` |

「内容为空即失败」的判定在服务端：图跑完但正文为空时发 `error` 而不是 `complete`（`StreamingChapterController.java:172-202`）；`errors` 里可能含非致命警告，不作为失败依据（`:176-179`）。

### 4.3 `checkpoint` 是「审批指令列表」，不是弹窗

- **服务端**：`NodeExecutor` 进入节点前调 `authorAgent.beforeNode(nodeName, state)` 拿到一条 `AuthorDirective`（`action`/`rationale`/`targetNode`），随即以事件推给前端（`ai/graph/NodeExecutor.java:34-50`）。`Action` 四值：`APPROVE`、`REVISE`、`REJECT`、`REDIRECT`（`ai/graph/AuthorDirective.java:16-21`）。
- **语义**：单向播报系统的判定与理由——`REDIRECT` 由服务端在 `afterNode` 注入状态继续执行（`NodeExecutor.java:117-135`），`REJECT` 直接跳过该节点（`:137-145`），都不需要人参与。
- **前端**：渲染为一排横向徽标（节点名→章纲审查/正文审查/终审决策，动作→通过/修订/驳回/重定向），`rationale` 挂在 `title` 上做悬浮提示（`NovelDetail.vue:357-366`）。**没有输入框、没有对话框，不要求作者当场回答。**
- **如实记录**：`beforeNode` 只在 `Mode.FULL` 下调用（`NodeExecutor.java:35`），流式走 `Mode.STREAMING`（`MultiAgentNovelService.java:157`），故**当前 SSE 流式路径实际不会发出 `checkpoint`**，前端该区域留空属预期。

### 4.4 向导 SSE 的事件

`progress`（当前章号/总数）、`outline`（单章章纲 JSON）、`complete`（`{"totalChapters":N}`）、`error`（`{"message":...}`），事件名在 `service/wizard/WizardServiceImpl.java:250-323`，前端 `switch` 分派在 `views/CreateNovelWizard.vue:644-660`。

## 5. 取消与保存流程

这是流式写作最容易误解的一段，下面按代码实际行为描述。

### 5.1 取消链路

```
用户点「取消生成」(NovelDetail.vue:375)
   │
   ├─ ① POST /api/chapter/cancel?novelId=<id>     ← 置位 Redis 取消标志，TTL 10 分钟
   │      controller/StreamingChapterController.java:221-225
   │
   └─ ② streamAbortController.abort()              ← 前端中断 fetch，停止读流
          frontend/src/views/NovelDetail.vue:924-935

服务端：SSE 连接被断开 → emitter.onError 回调 → cancelFlag.set(true)
        controller/StreamingChapterController.java:114-117

图执行器：每个节点边界检查 cancelFlag，为真则跳出循环并停止后续节点
        ai/graph/GraphRunner.java:79-84
```

要点：

- `POST /chapter/cancel` 写 Redis 键 `<前缀>novel:cancel:<novelId>`，值 `"1"`，10 分钟过期（`StreamingChapterController.java:223`；键名见 `config/RedisKeyProvider.java:36-38`）；同键在下一次流式请求开始时被删除（`:119-123`）。
- **真正让图停下来的是 SSE 连接断开**：前端 abort 后服务端 `onError` 把内存里的 `cancelFlag`（`AtomicBoolean`）置位，塞进图状态（`service/chapter/MultiAgentNovelService.java:146-151`），`GraphRunner` 在**每个节点边界**读它并 `break`（`GraphRunner.java:81-84`）。即：**取消是「停在下一次节点边界」，不是「掐断正在进行的 LLM 流」**。
- 超时同理：`onTimeout` 也置位并补发一个 `error` 事件（`StreamingChapterController.java:105-112`）。

### 5.2 落库的两条路径

| 场景 | 是否落库 | 由谁落库 |
| --- | --- | --- |
| 正常跑完（收到 `complete`） | 是 | 后端图的 `post_process` 节点调用 `chapterSaveService.saveGenerationResultAsync(...)`（`ai/graph/PostProcessNode.java:64-75`），前端只做刷新（`NovelDetail.vue:937-943`，提示语即「章节已自动保存」） |
| 取消 / 出错（图没跑到 `post_process`） | 否 | **必须由前端手动调用 `POST /api/chapter/stream-save`**，把缓冲区里的正文提交保存（`StreamingChapterController.java:230-264`；前端 `NovelDetail.vue:946-978`） |

关键结论（不要写反）：

1. **取消后已生成的内容留在前端缓冲区**（`streamingContent`，`NovelDetail.vue:515`），后端不会替你在流式路径上自动补存——图在 `post_process` 之前就被截断。
2. 流式对话框在「已取消/出错」分支才显示「保存已生成内容」按钮（`NovelDetail.vue:384-388`），点击后走 `stream-save`，服务端补算摘要与字数后写库（`StreamingChapterController.java:242-263`）。
3. **浏览器直接关闭**页面/标签页时缓冲区随内存消失，未落库内容一并丢失——无本地持久化兜底（`ChapterEdit.vue` 的 localStorage 草稿只服务手工编辑页）。
4. 重写场景下流式开始前会先给旧章节存版本快照（`StreamingChapterController.java:125-136`），误覆盖可从历史版本回滚（`ChapterDetail.vue:77-95`）。

## 6. 并发控制

- 服务端维护一张「进行中的流式任务表」，键为 **`<novelId>:<chapterNum>`**（`StreamingChapterController.java:67,89`）。
- 提交时用 `putIfAbsent` 抢占：键已存在说明同一本小说的同一章正在生成，**直接拒绝**，返回一个只含 `error` 事件的 emitter（提示「该章节正在生成中，请勿重复提交」）并立即 `complete()`（`StreamingChapterController.java:90-98`）。
- 任务结束（无论成功、失败、异常）在 `finally` 中移除键（`StreamingChapterController.java:210-212`）。
- 任务体在 `securityContextIoExecutor` 线程池中异步执行，SSE 线程只负责收发（`StreamingChapterController.java:121-213`）。
- 前端另有一层保护：发起新的流式请求前，先 abort 掉上一个未结束的请求（`NovelDetail.vue:746-750`）。
- 该表是**进程内内存表**，未做跨实例分布式锁；同一章节在多实例部署下的互斥依赖前置网关。

## 7. 鉴权与访问控制

### 7.1 JWT

- `AuthFilter` 读 `Authorization: Bearer <token>`，验签后把 `userId`/`username`/`role` 塞进请求属性，并写入 Spring Security 上下文，权限名为 `ROLE_<role>`（`config/AuthFilter.java:43-65`）。
- Token 由 `jwtConfig.generateToken(userId, username, role)` 签发，claims 为 `sub`/`username`/`role`，默认有效期 24 小时（`config/JwtConfig.java:20-27,53-65`）。
- 签名密钥长度不足 32 字节或仍是示例值时，服务启动直接失败（`JwtConfig.java:29-47`）。

### 7.2 RBAC 规则

`SecurityConfig` 的授权声明（`config/SecurityConfig.java:35-42`）：

| 规则 | 路径 |
| --- | --- |
| 公开 | `/auth/login`、`/auth/register`、`/genre/**`、`/genre-template/**`、`/error` |
| 需登录 | `/mcp/**`、`/style-card/**`、`/novel/**`、`/llm-config/**`、`/chapter/**`、其余全部 |
| 需 admin 角色 | `/admin/**` |

方法级注解另有两条 `@PreAuthorize("hasRole('ADMIN')")`：`GenreController.reload`（`controller/GenreController.java:45-47`）、`StyleCardController.fixDoubleEncoding`（`controller/StyleCardController.java:280-282`）。
未认证返回 401、无权限返回 403，均为 JSON 体（`SecurityConfig.java:43-54`）。
另外单独放行 ASYNC/ERROR dispatch，避免 SSE 断连后 error page 触发 `AccessDeniedException`（`SecurityConfig.java:63-72`；`AuthFilter.java:32-36`）。

**角色取值**：注册用户默认角色为 `user`（`service/user/UserServiceImpl.java:52`），管理员为 `admin`。如实记录一处细节：路径规则写的是 `hasRole("admin")`（小写），方法级注解写的是 `hasRole('ADMIN')`（大写），两者在 Spring Security 中是**大小写敏感的不同权限**，当前实现依赖角色字面量与请求路径的对应关系。

### 7.3 资源归属校验

`OwnerAccessInterceptor` 挂在 `/novel/**`、`/llm-config/**`、`/chapter/**`、`/style-card/**` 上（`config/WebConfig.java:44-52`），从路径变量里取 `novelId` / `configId` / `cardId`，比对属主，不匹配直接 403（`interceptor/OwnerAccessInterceptor.java:38-79`），归属查询带 5 分钟本地缓存（`:31-34,81-103`）。
`/novel/list`、`POST /novel`、`/novel/auto-generate-outline` 被排除（列表已按 userId 过滤，另两个不带资源 ID）（`WebConfig.java:48-52`）。
`LlmConfigController` 内部还做了二次归属校验（更新/删除时比对 `userId`，不允许改 owner）（`controller/LlmConfigController.java:49-58,73-80`）。

### 7.4 协同编辑的权限边界

**如实记录**：当前系统**没有协同编辑（多人共写同一本小说）功能**——全仓库不存在协作者、共享、邀请等概念，权限模型是「单所有者 + 管理员」：小说、模型配置、文风卡片都只有一个 owner，非属主访问一律 403（`interceptor/OwnerAccessInterceptor.java:51-76`）。因此不存在「多人同时编辑同一章」的冲突处理分支。

## 8. 已知边界（如实记录）

| 边界 | 说明 |
| --- | --- |
| **没有独立的「生成轨迹时间线」页面** | 路由表无轨迹页（`router/index.ts:7-84`）。轨迹的**节点序列**在非流式生成路径里被拼进 `plotFingerprint` 返回（`service/chapter/MultiAgentChapterGenerationService.java:34-37,152-153`，形如 `arc_check → outline → writing`）；章节接口本身**不返回**轨迹字段（`dto/response/ChapterResponse.java:16-40`）。章节详情页展示的是**剧情摘要** `plotFingerprint`（别名 `summary`）（`views/ChapterDetail.vue:29-32`；`ChapterResponse.java:35,49-53`） |
| **节点级耗时以服务端日志为准** | `NodeExecutionRecord` 带起止时间（`ai/graph/NodeExecutionRecord.java:7-35`），但只在服务端流转，日志由 `GraphRunner`/`NodeExecutor` 打印（`ai/graph/GraphRunner.java:103,119`），**不回传前端** |
| **没有生成过程的暂停 / 继续** | 前端只有「取消」，无暂停按钮与恢复协议；服务端 checkpoint（Redis 存图状态，TTL 1 小时，`ai/graph/StateCheckpointService.java:19,35-50`）只在 FULL 模式**自动**用于下次运行的断点恢复（`ai/graph/GraphRunner.java:52-70`），并非用户可操纵的暂停/继续 |
| **没有按用户维度的配额限流** | 全仓库无 RateLimit / 配额 / 令牌桶；并发控制只到「同一本小说的同一章同时只能有一个流式任务」（第 6 节）。批量生成的取消是另一套 Redis 键（`service/wizard/WizardServiceImpl.java:418-421,482-484`） |
| **流式路径不自动保存被取消的内容** | 见 5.2：取消后必须由前端显式调 `stream-save`；浏览器关闭则缓冲区丢失 |
| **`checkpoint` 事件当前不会出现在流式对话里** | `beforeNode` 仅在 FULL 模式调用（`ai/graph/NodeExecutor.java:35`），流式走 STREAMING（`service/chapter/MultiAgentNovelService.java:157`） |
| **前端保留了一个后端未发出的事件分支** | `NovelDetail.vue:834-842` 仍处理 `validation_result`，但后端无对应发送点，属兼容预留 |
| **`/admin/**` 路径规则当前无对应控制器** | 仓库无映射到 `/admin/**` 的 controller，管理员能力目前只体现为两处 `@PreAuthorize`（`controller/GenreController.java:45`、`controller/StyleCardController.java:281`） |
