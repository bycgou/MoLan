# 01 · 总体架构

> 摘要：MoLan 是一个模块化单体形态的长篇小说创作系统——Spring Boot 后端内置自研写作图编排引擎，驱动「章纲 → 规划 → 写作 → 门禁 → 审校 → 摘要」的多 Agent 章节生成流程；Vue 3 前端提供建书与写作界面；业务主数据、创作记忆、向量检索、运行态缓存分别落在 MySQL、MongoDB、Milvus、Redis 四类存储上。

本文描述的是仓库当前的**实现态**。全文论断均给出 `相对仓库根的路径:行号` 证据；未实现的能力一律不写入，各个子系统的详细设计见同目录其余分篇。

---

## 1. 系统定位与能力边界

一句话定位：把「写一章长篇小说」显式建模成一张有向图，用多个专职 Agent 分别负责章纲、正文、摘要、卷纲与卷级规划，并在图上挂载事实锁、跨章连续性、七维加权评分等质量关口，使作品写到几十章之后仍保持设定自洽（`README.md:5`）。

| 维度 | 是什么 | 不是什么 |
| --- | --- | --- |
| 交互形态 | 面向「持续创作一部作品」的工程系统：向导建书 → 分卷 → 逐章生成 → 记忆沉淀 → 一致性校验 | **不是通用聊天机器人**：所有 LLM 调用都绑定固定任务契约（章纲 / 正文 / 摘要 / 卷纲 / 五重校验），对外默认只暴露 REST 资源接口，MCP 服务端默认关闭（`backend/src/main/resources/application.yml:223`、`backend/src/main/java/com/novel/system/ai/agent/OutlineAgent.java:51`、`backend/src/main/java/com/novel/system/ai/chain/ChapterGenerationChain.java:68`、`backend/src/main/java/com/novel/system/controller/NovelController.java:30`） |
| 生成方式 | 节点化、可路由、可重试、可留痕的图执行（`backend/src/main/java/com/novel/system/ai/graph/GraphRunner.java:75`、`backend/src/main/java/com/novel/system/service/chapter/MultiAgentNovelService.java:38`） | **不是「一次调用出一段文字」的写作工具**：一次生成要穿过若干节点与质量关口，失败按节点粒度重试并写入错误流水（`backend/src/main/java/com/novel/system/ai/graph/NodeExecutor.java:74`） |
| 模型接入 | 用户在界面自配 OpenAI 兼容模型，配置落库（`backend/src/main/java/com/novel/system/entity/mysql/LlmConfig.java:35`） | **不跨模型调度、不做容灾切换**：一次生成只绑定一个模型配置，取不到可用模型即抛出异常，由用户自行修正配置（`backend/src/main/java/com/novel/system/ai/graph/ChatModelProvider.java:38`） |
| 运行状态 | 同步生成 / SSE 流式 / 取消三种运行形态，一次请求一次图执行 | 不是常驻会话式服务：生成过程由后端在单次请求内跑完 |

## 3. 分层架构

```
controller/  ──▶  service/  ──▶  mapper/ + entity/mysql/      (业务主数据)
   (REST)         (领域业务)  └─▶ repository/mongo/ + entity/mongo/  (创作记忆)
                        │
                        ├──▶ ai/graph/   (图编排引擎、节点、Agent 钩子)
                        ├──▶ ai/agent/  (单次 LLM 调用契约)
                        ├──▶ ai/chain/  (链式调用与校验服务)
                        ├──▶ ai/rag/    (向量检索)
                        ├──▶ ai/memory/ (角色图谱、文风记忆)
                        ├──▶ ai/deslop/ (反 AI 味规则)
                        └──▶ ai/tool/   (工具封装)
```

| 层 | 包路径 | 职责 | 调用约定与证据 |
| --- | --- | --- | --- |
| 接入层 | `controller/` | REST 解析、参数校验、鉴权上下文、SSE 通道；不含业务规则 | 薄包装，只委托 service 并返回统一 `ApiResponse`（`backend/src/main/java/com/novel/system/controller/ChapterController.java:26`） |
| 应用/业务层 | `service/` | 领域业务：章节、伏笔、角色、风格、流派、故事状态、记忆账本、向导、模型配置 | 可调用 mapper / repository，也可触发一次图执行（`backend/src/main/java/com/novel/system/service/chapter/MultiAgentChapterGenerationService.java:67`） |
| 编排与能力层 | `ai/` | 图编排（`graph`）、LLM 调用契约（`agent`/`chain`）、检索（`rag`）、记忆（`memory`）、规则（`deslop`）、工具（`tool`） | 节点只做「取上下文 → 调模型 → 写状态」，持久化一律回调 service（`backend/src/main/java/com/novel/system/ai/graph/WritingNode.java:24`） |
| 数据层 | `mapper/`、`entity/`、`repository/` | MySQL 走 mapper + `entity/mysql`，MongoDB 走 `repository/mongo` + `entity/mongo` | mapper 不含业务判断（`backend/src/main/java/com/novel/system/mapper/NovelBaseMapper.java:9`、`backend/src/main/java/com/novel/system/mapper/UserMapper.java:10`）；实体标注表名 / 集合名（`backend/src/main/java/com/novel/system/entity/mysql/NovelBase.java:13`、`backend/src/main/java/com/novel/system/entity/mongo/StoryState.java:19`） |

**`ai/` 与 `service/` 的边界**：`ai/` 回答「怎么编排、怎么调模型」，`service/` 回答「业务是什么、数据怎么落」。图节点不认识 HTTP，也不直接拼装业务主数据表；它们通过注入的 service 取记忆与配置（如 `backend/src/main/java/com/novel/system/ai/graph/WritingNode.java:24`、`backend/src/main/java/com/novel/system/ai/graph/ValidationNode.java:30`）。反向依赖只有一处形态——service 通过 `MultiAgentNovelService` 发起一次图执行，图返回的状态再由 service 落库。

## 4. 四库职责边界

| 存储 | 装什么 | 不装什么 | 典型对象 | 证据 |
| --- | --- | --- | --- | --- |
| **MySQL** | 业务主数据：需要唯一约束、排序、分页、关联语义的数据 | 过程态记忆、向量 | `novel_base`、`novel_chapter`、`novel_arc`、`clue_book`、`style_card`、`llm_config`、`sys_user`、`chapter_versions`、`world_clock`、`arc_summaries` | `backend/src/main/java/com/novel/system/entity/mysql/NovelBase.java:13`、`backend/src/main/java/com/novel/system/entity/mysql/NovelChapter.java:12`、`backend/src/main/java/com/novel/system/entity/mysql/ClueBook.java:12`、`backend/src/main/java/com/novel/system/entity/mysql/LlmConfig.java:12`、`backend/src/main/java/com/novel/system/entity/mysql/User.java:12`、`backend/src/main/java/com/novel/system/entity/mysql/ArcSummary.java:15` |
| **MongoDB** | 创作记忆：结构随创作演进、整文档读写、字段可嵌套 | 需要强关系约束的主数据、章节正文原文 | `story_state`、`fact_lock`、`emotion_ledger`、`completed_beats`、`character_state`、`character_voice_samples`、`event_graph`、`chapter_summary`、`novel_graph`、`arc_orchestrations` | `backend/src/main/java/com/novel/system/entity/mongo/StoryState.java:19`、`backend/src/main/java/com/novel/system/entity/mongo/FactLock.java:13`、`backend/src/main/java/com/novel/system/repository/mongo/StoryStateRepository.java:9` |
| **Milvus** | 仅章节摘要的稠密向量与检索元数据 | 正文、业务表、结构化查询 | 集合 `novel_summary`，维度 1024，度量 COSINE | `backend/src/main/resources/application.yml:94`、`backend/src/main/resources/application.yml:95`、`backend/src/main/resources/application.yml:96`、`backend/src/main/java/com/novel/system/ai/rag/MilvusVectorStoreServiceImpl.java:102` |
| **Redis** | 运行态：图检查点、上下文缓存、异步任务状态、向导批量进度、取消标记 | 任何需要长期保存的业务数据 | 键前缀统一由 `RedisKeyProvider` 拼接：检查点 / 上下文 / 任务状态 / 向导批次 / 取消 | `backend/src/main/java/com/novel/system/config/RedisKeyProvider.java:12`、`backend/src/main/java/com/novel/system/config/RedisKeyProvider.java:20`、`backend/src/main/java/com/novel/system/ai/graph/StateCheckpointService.java:19`、`backend/src/main/resources/application.yml:69` |

**为什么这么切**：主数据要稳定（表结构、约束、索引），所以放关系库；创作记忆是随故事长出来的半结构化文档，字段会不断新增，放文档库最省改造成本；「语义召回」本质是近似最近邻，交给专用向量库而不是用 SQL 硬凑；检查点与缓存是可丢弃的运行态，放内存库并在 1 小时后自然过期，坏了不影响作品数据。向量写入发生在摘要落库路径上（`backend/src/main/java/com/novel/system/ai/rag/RagServiceImpl.java:484`），检索为「向量 + BM25 + RRF」混合召回（`backend/src/main/java/com/novel/system/ai/rag/RagServiceImpl.java:27`）。

四库的字段级设计、键空间与已知边界，详见 `08-数据模型与存储边界.md`。

| 形态 | 入口 | 用户可见行为 | 实现要点 |
| --- | --- | --- | --- |
| **同步生成** | `POST /novel/{novelId}/chapter` | 阻塞直到整章跑完，一次返回正文、字数与质量分 | 走 `Mode.FULL` 全图（`backend/src/main/java/com/novel/system/service/chapter/MultiAgentChapterGenerationService.java:67`、`backend/src/main/java/com/novel/system/ai/graph/Mode.java:6`）；另有异步接口 `POST /novel/{novelId}/chapter/async` 与状态查询，状态存 Redis（`backend/src/main/java/com/novel/system/controller/NovelController.java:169`、`backend/src/main/java/com/novel/system/config/RedisKeyProvider.java:28`） |
| **SSE 流式** | `POST /chapter/stream-write` | 正文边生成边推送到浏览器，结束收到 `complete` 或 `error` 事件；同一小说同一章节不允许并发提交（`backend/src/main/java/com/novel/system/controller/StreamingChapterController.java:90`） | `SseEmitter` 超时 10 分钟（`backend/src/main/java/com/novel/system/controller/StreamingChapterController.java:100`），走 `Mode.STREAMING` 轻量校验路径（`backend/src/main/java/com/novel/system/service/chapter/MultiAgentNovelService.java:157`） |
| **取消** | 断开 SSE 连接 / `POST /chapter/cancel` | 连接异常或超时时，图在下一个节点边界停止；`/chapter/cancel` 在 Redis 写取消标记（10 分钟有效） | 连接异常置取消标志（`backend/src/main/java/com/novel/system/controller/StreamingChapterController.java:114`），图执行循环在每个节点前检查该标志（`backend/src/main/java/com/novel/system/ai/graph/GraphRunner.java:80`），取消接口见 `backend/src/main/java/com/novel/system/controller/StreamingChapterController.java:221` |

补充两点边界：图定义了 `FAST`（跳过校验）、`STREAMING`（轻量校验）、`FULL`（完整多 Agent）三档模式（`backend/src/main/java/com/novel/system/ai/graph/Mode.java:3`），但当前两个入口只会选中 `FULL` 与 `STREAMING`；检查点断点恢复只在 `FULL` 下触发（`backend/src/main/java/com/novel/system/ai/graph/GraphRunner.java:53`），SSE 流式不会从检查点续写。
