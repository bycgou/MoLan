# 07 · 质量门禁与审校路由

> 正文写出来之后，系统还要回答一个问题：**这一稿能不能交？** 本章描述正文生成之后的所有质量关口、它们的拦截能力，以及当审校不通过时结论如何回到下一轮写作里。
>
> 全文只描述当前实现态。判定逻辑的权威是 `backend/src/main/java/com/novel/system/ai/graph/GradedAuditCalculator.java`，反 AI 味规则的权威是 `backend/src/main/resources/deslop/deslop-rules.yaml`。

## 1. 门禁体系总览

生产图（`Mode.FULL`）的门禁链是一条**线性主干 + 四条回边**（`deslop_check→writing`、`self_review→writing`、`audit_router→writing`、`audit_router→outline`；拓扑声明见 `backend/src/main/java/com/novel/system/service/chapter/MultiAgentNovelService.java:38-80`）：

```
arc_check ─► outline ─► [clue_planning ‖ character_planning] ─► world_validate
                                                                     │
                                                                     ▼
   ┌─────────────────────────────────────────────────────────────────────┐
   │  writing ─► deslop_check ─► self_review ─► continuity_validation      │
   │     ▲           │              │                    │                  │
   │     │           │(REWRITE)     │(HIGH)              │                  │
   │     └───────────┴──────────────┘                    ▼                  │
   │                                                validation ─► quality_scoring
   │                                                     │                    │
   │                                                     ▼                    ▼
   │                                              audit_router ──(REPLAN)─► outline
   │                                          (PASS)│  (REWRITE)──► writing
   │                                                ▼
   │                                     fact_lock_violation ─► summary
   └─────────────────────────────────────────────────────────────────────┘
```

## 2. 反 AI 味：规则表驱动的七层防御

### 2.1 为什么不用 LLM 判断「AI 味」

「这句话像不像 AI 写的」如果交给模型判断，会同时踩三个坑：**每次判定都要花钱**、**判定不可复现**（同一段文字两次结论可能不同）、**判定不可回归**（无法回答「这条规则加了以后误报率是升是降」）。因此本项目把反 AI 味做成**数据化规则表**：规则是 YAML，检测是纯正则/密度计算，`MechanicalDeslopDetector` 是纯函数（不读文件、不发调用），可以直接在对照集上复算误报率（`backend/src/main/java/com/novel/system/ai/deslop/MechanicalDeslopDetector.java:10-18`）。

规则表自身也承认「证据会过期」——注释里直接写明模型换代会让某些 AI 特征消失，因此每条规则都带 `evidence` 字段，改规则 = 改 YAML，diff 可审查（`backend/src/main/resources/deslop/deslop-rules.yaml:1-24`）。当前表版本 `version: 2`，共 **54 条规则**：`blocking` 2 条、`major` 29 条、`advisory` 23 条；全部为 `review: mechanical`；其中 15 条是密度判据、3 条限定 `scope: chapter_tail`。

### 2.2 七层映射

代码里并没有一个叫「七层」的类；下面是把现有实现按职责切开的七层，每层都有独立代码单元：

| 层 | 职责 | 代码位置 |
| --- | --- | --- |
| L1 规则表（数据） | 规则 id / scope / severity / 判据 / message / suggestion / evidence | `backend/src/main/resources/deslop/deslop-rules.yaml` |
| L2 加载期一致性校验 | 校验规则表本身是否自洽，不通过则加载失败 | `backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:92-176` |
| L3 规则表供给 | 懒加载 + 缓存，校验失败在启动阶段冒泡 | `backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetProvider.java:31-55` |
| L4 机械检测层 | 三种判据：pattern / density / detector | `backend/src/main/java/com/novel/system/ai/deslop/MechanicalDeslopDetector.java:72-104` |
| L5 统计指标层 | 整章分布类指标（句长多样性、对白占比……） | `backend/src/main/java/com/novel/system/ai/deslop/DeslopMetricThresholds.java:46-87` |
| L6 严重度分层与路由接入 | 判定是否挡稿、是否请求重写 | `backend/src/main/java/com/novel/system/ai/deslop/DeslopSeverity.java:9-15`、`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:72-115` |
| L7 离线自检与回归 | 不依赖 Spring/DB 跑规则表与检测器 | `backend/src/main/java/com/novel/system/ai/deslop/DeslopSelfCheck.java:33-52` |

### 2.3 规则表结构

一条规则由 `DeslopRule` 定义（`backend/src/main/java/com/novel/system/ai/deslop/DeslopRule.java:25-54`）：

| 字段 | 含义 | 取值约束 |
| --- | --- | --- |
| `id` | 规则标识 | kebab-case，加载期正则校验（`backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:32`、`backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:94-96`） |
| `severity` | 严重度 | `blocking` / `major` / `advisory`（`backend/src/main/java/com/novel/system/ai/deslop/DeslopSeverity.java:9-15`） |
| `review` | 复核方式 | `mechanical`（可代码判定）/ `semantic`（需语境理解）（`backend/src/main/java/com/novel/system/ai/deslop/DeslopReview.java:9-11`） |
| `scope` | 生效范围 | `full`（默认）/ `chapter_tail`（仅正文末 N 段）（`backend/src/main/java/com/novel/system/ai/deslop/DeslopScope.java:9-13`） |
| `pattern` / `density` / `detector` | 三种判据 | **必须恰好给一个**，否则加载失败（`backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:105-109`） |
| `autofix` | 自动修复方式 | 当前只支持 `delete`，且只允许作用于密度规则（`backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:130-142`） |
| `message` / `suggestion` / `languages` / `evidence` | 提示语、改法、语言、依据 | `message`/`suggestion` 必填（`backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:144-151`） |

典型条目：

- `trailer-ending`：`blocking` + `scope: chapter_tail`，拦「章末总结体/预告体」（`backend/src/main/resources/deslop/deslop-rules.yaml:47-55`）；
- `ai-self-reference`：`blocking`，拦正文里的模型自指/提示词泄漏，注释写明「误伤概率接近零」（`backend/src/main/resources/deslop/deslop-rules.yaml:247-256`）；
- `not-is-comparison`：`advisory`，理由写进 `evidence` ——「人类文章也出现，作 blocking 会把合法修辞卡死」（`backend/src/main/resources/deslop/deslop-rules.yaml:34-45`）；
- `filler-adverb-density`、`emphasis-filler-density`：唯一两条带 `autofix: delete` 的规则（`backend/src/main/resources/deslop/deslop-rules.yaml:495-506`、`backend/src/main/resources/deslop/deslop-rules.yaml:556-567`）。注意：**当前只出提案、不自动改稿**（`backend/src/main/resources/deslop/deslop-rules.yaml:13-14`）。

### 2.4 加载期一致性校验（铁律）

`DeslopRulesetLoader` 在解析时强制三条铁律，任何一条不满足直接抛异常（**报错而不是带病运行**）：

| 铁律 | 代码 | 含义 |
| --- | --- | --- |
| 一：`blocking` 只允许 `review: mechanical` | `backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:121-124` | 语义判断永远不能挡稿 |
| 二：`review: semantic` 一律 `advisory` | `backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:125-128` | 需要语境判断的规则不能自动加重 |
| 三：`autofix` 只允许给 density 规则，且须 `mechanical` 且非 `blocking` | `backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:130-142` | 自动修复不得作用于逐处判据，也不得碰挡稿判据 |

外加两条结构约束：判据三选一必须恰好一个（`backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:105-109`）；`detector` 只认已实现白名单 `sentence_length_run`（`backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:27`、`backend/src/main/java/com/novel/system/ai/deslop/DeslopRulesetLoader.java:110-113`）。

**离线自检入口**是 `DeslopSelfCheck`：它不依赖 Spring、不依赖数据库，用内置样例或指定文本文件跑一遍「加载规则表 → 扫描 → 打印命中与 blocking 计数」，可在跑不起完整服务的环境里单独验证规则表与检测器（`backend/src/main/java/com/novel/system/ai/deslop/DeslopSelfCheck.java:23-52`）。

### 2.5 机械判据怎么算

- **pattern**：逐处匹配，每条规则每章最多报 `MAX_HITS_PER_RULE = 5` 处，命中片段截断到 60 字（`backend/src/main/java/com/novel/system/ai/deslop/MechanicalDeslopDetector.java:25-28`、`backend/src/main/java/com/novel/system/ai/deslop/MechanicalDeslopDetector.java:106-117`、`backend/src/main/java/com/novel/system/ai/deslop/MechanicalDeslopDetector.java:194-203`）。
- **density**：基线 = `limit × (字数 / per)`，命中数超过基线才报（`backend/src/main/java/com/novel/system/ai/deslop/DeslopDensity.java:31-33`、`backend/src/main/java/com/novel/system/ai/deslop/MechanicalDeslopDetector.java:119-140`）。例如「每 1000 字 ≤3 处」的弱化副词（`backend/src/main/resources/deslop/deslop-rules.yaml:68-78`）。
- **detector**：目前只有 `sentence_length_run`——连续 ≥3 句、每句与该连句首句长度差 < 15% 判为句长复读（`backend/src/main/java/com/novel/system/ai/deslop/MechanicalDeslopDetector.java:37`、`backend/src/main/java/com/novel/system/ai/deslop/MechanicalDeslopDetector.java:146-181`）。
- **对话豁免**：按**等长遮罩**处理，把 `「…」` 等引号内容替换成等长空格，字符位置不变，因此「章末 N 段」的范围与密度的字数分母不会漂移（`backend/src/main/java/com/novel/system/ai/deslop/MechanicalDeslopDetector.java:40-65`）。
- **章末范围**：`scope: chapter_tail` 的规则只扫最后 `deslop.tail-paragraphs` 段（默认 3，`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:45`、`backend/src/main/java/com/novel/system/ai/deslop/MechanicalDeslopDetector.java:77-83`）。

统计指标层另出 6 条 advisory 结论（句长多样性、连续对白段数、对白占比、过渡词套话占比、空场景占比、章末收束形态），阈值是**代码里的固定常量**，不从风格卡读，避免同一段文字在不同卡片下打出不同分（`backend/src/main/java/com/novel/system/ai/deslop/DeslopMetricThresholds.java:9-36`、`backend/src/main/java/com/novel/system/ai/deslop/DeslopMetricThresholds.java:46-87`）。

## 3. 严重度与拦截语义

| 严重度 | 语义 | 是否挡稿 |
| --- | --- | --- |
| `blocking` | 强模板短语，几乎不可能误伤 | **是**——可触发重写 |
| `major` | 该改但不致命 | 否，只计数与出建议 |
| `advisory` | 只计数出提示，不参与任何路由 | 否（枚举注释即如此定义，`backend/src/main/java/com/novel/system/ai/deslop/DeslopSeverity.java:9-15`） |

拦截由 `DeslopCheckNode` 决定（`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:72-115`）：

1. 统计 `blocking` 命中数，为 0 → 决策 `PASS`；
2. `blocking > 0` 但 `deslop.enforce=false` → 只记录，决策仍为 `PASS`（代码默认 false，生产配置为 true）；
3. `blocking > 0` 且 `deslop.enforce=true` → 若 `deslopRewriteCount >= deslop.max-rewrites` → 决策 `REWRITE_EXHAUSTED`（放行）；否则决策 `REWRITE`，重写计数 +1。

**重写条件边**：`deslop_check --REWRITE--> writing`（`backend/src/main/java/com/novel/system/service/chapter/MultiAgentNovelService.java:48-49`），谓词是 `"REWRITE".equals(state.getDeslopDecision())`。走这条边时，门禁把命中项格式化成带逐字引用的修订意见并**合并**进 `pendingRevisionNotes`（`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:102-115`、`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:131-149`）。

**预算独立性**：deslop 的重写预算由 `deslop.max-rewrites` 单独控制，不占 `writing` 的重试配额，避免把自审的重写机会吃光（`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:25-27`、`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:44`、`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:93-100`）。

## 4. 七维加权审校

### 4.1 维度、权重与严重度

默认配置见 `backend/src/main/java/com/novel/system/ai/graph/ValidationConfig.java:18-26`，与 `backend/src/main/resources/application.yml:163-173` 一致（键名：`novel.validation.use-graded-audit`、`novel.validation.pass-threshold`、`novel.validation.dimensions.*`）：

| 维度 | 权重 | 严重度 | 分数来源 |
| --- | --- | --- | --- |
| `ooc` 人设一致性 | 0.20 | **FATAL** | OOC 四项均分总分（0–100），通过阈值 70（`backend/src/main/java/com/novel/system/ai/chain/ValidationServiceImpl.java:35`、`backend/src/main/java/com/novel/system/ai/chain/ValidationServiceImpl.java:415-417`） |
| `logic` 逻辑 | 0.20 | **FATAL** | 通过记 100，否则 0 |
| `setting` 设定 | 0.15 | **FATAL** | 通过记 100，否则 0 |
| `clue` 伏笔 | 0.15 | WARNING | 通过记 100，否则 0 |
| `rhythm` 节奏 | 0.10 | WARNING | 通过记 100，否则 0 |
| `quality` 质量 | 0.10 | WARNING | 质量总分（0–100） |
| `clueLanding` 伏笔落地 | 0.10 | WARNING | 通过记 100，否则 0 |

权重之和为 1.0。FATAL 三项（ooc/logic/setting）合计 0.55，WARNING 四项合计 0.45。

### 4.2 加权分公式

代码里的公式只有一行累加（`backend/src/main/java/com/novel/system/ai/graph/GradedAuditCalculator.java:38-48`）：

```
weightedScore = Σ (维度得分 × 维度权重)
```

其中「维度得分」按上表取值：FATAL/WARNING 中的二值维度通过记 100、不通过记 0；`ooc` 与 `quality` 用连续分。因此满分是 100。

通过判据（`backend/src/main/java/com/novel/system/ai/graph/GradedAuditCalculator.java:50-53`）：

```
allPassed = (fatalFailures 为空) && (weightedScore >= passThreshold)   // passThreshold 默认 60.0
```

**关键语义**：WARNING 维度不通过**不直接拦稿**，它只把分数拉低；只有当拉低后总分跌破阈值才判不通过。测试固化了这一点：单条 clue 失败（加权 79）仍然通过；clue+rhythm+quality 三项同时失败（加权 59）才不通过（`backend/src/test/java/com/novel/system/ai/graph/GradedAuditCalculatorTest.java:74-110`）。`warnings` 列表会被记录但**不参与路由**（`backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:76-97` 未读 `getWarnings()`）。

### 4.3 数据从哪来

`validation` 节点一次发起五个并行 LLM 校验（OOC/逻辑/伏笔/设定/节奏），整体超时 120 秒，任一异常都记为不通过（`backend/src/main/java/com/novel/system/ai/chain/ValidationServiceImpl.java:172-287`）。`quality_scoring` 节点产出质量总分与伏笔落地结论（`backend/src/main/java/com/novel/system/ai/graph/QualityScoringNode.java:45-90`）。两者写进 `AuditResult`，由 `GradedAuditCalculator` 统一折算（`backend/src/main/java/com/novel/system/ai/graph/GradedAuditCalculator.java:17-36`）。

## 5. 审校路由决策表

`AuditRouterNode` 有两条路由实现：`novel.validation.use-graded-audit=true` 走 `gradedRoute`（默认），关闭则退回 `legacyRoute`（`backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:57-61`）。

### 5.1 分级路由（默认）

| 条件 | 决策 | 去向 | 计数 |
| --- | --- | --- | --- |
| 存在 FATAL 失败维度，且 `planRetryCount < 3` | **REPLAN** | 退回 `outline` 重新规划 | `planRetryCount+1`、`iterationCount+1` |
| 存在 FATAL 失败维度，且 `planRetryCount >= 3` | **MANUAL_REVIEW** | 落到 `audit_router` 的兜底节点 `fact_lock_violation`，继续走完流程 | — |
| 无 FATAL 失败但加权分 < 阈值，且 `rewriteCount < 2` | **REWRITE** | 回到 `writing` 重写 | `rewriteCount+1`、`iterationCount+1` |
| 无 FATAL 失败但加权分 < 阈值，且 `rewriteCount >= 2` | **MANUAL_REVIEW** | 落到 `audit_router` 的兜底节点 `fact_lock_violation`，继续走完流程 | — |
| 加权分 ≥ 阈值且无 FATAL 失败 | **PASS** | 进入 `fact_lock_violation` | — |

（常量：`MAX_REWRITES = 2`、`MAX_PLAN_RETRIES = 3`，`backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:23-25`；判定代码 `backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:76-97`；拓扑接线 `backend/src/main/java/com/novel/system/service/chapter/MultiAgentNovelService.java:61-67`）

> **MANUAL_REVIEW 并不停图。** 它不匹配任何一条条件边（生产图只定义了 PASS / REPLAN / REWRITE 三条），于是走 `GraphRunner` 的兜底分支（`backend/src/main/java/com/novel/system/ai/graph/GraphRunner.java:246-250`），落到 `audit_router` 的兜底节点 `fact_lock_violation`——**仍然经过事实锁校验**，再经 `summary → post_process` 收尾落库。它的语义是"审校不再自动重试，交由一致性门兜底并放行"，不是"章节被丢弃"或"停在这里等人工"。另外，它与图级 `writing` 预算耗尽不同：那一条会在 `state.getErrors()` 里留下"强制放行"错误记录，MANUAL_REVIEW 这条路径不产生同类错误。

### 5.2 legacy 路由（`use-graded-audit=false`）

写前校验未通过 → REPLAN；OOC/设定未通过 → REPLAN；审校未通过或质量分 < 60 → REWRITE；重写次数达上限 → MANUAL_REVIEW（`backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:100-134`）。

## 6. 审校意见回灌（反馈链）

审校最贵的一环是 LLM 校验；如果结论不进入下一轮写作，这一环就在空转。因此 `AuditRouterNode` 在 REWRITE **和 REPLAN** 两条路径上都会把结论写进 `pendingRevisionNotes`。

**方法级证据**：

| 步骤 | 代码 | 说明 |
| --- | --- | --- |
| 1. 组装意见 | `backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:180-237` `buildAuditNotes` | 顺序固定：**致命失败 → 未通过维度明细 → 伏笔落地问题 → 审校建议 → 总体评价**；空值直接跳过 |
| 2. 维度明细 | `backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:239-245` `addDimensionNote` | 五重校验中未通过的人设/逻辑/伏笔/设定/节奏各自产出一条 |
| 3. 致命项取细节 | `backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:248-263` `dimensionDetail` | 按维度名取对应明细文本，致命失败那条必须带上细节才好改 |
| 4. **合并**而非覆盖 | `backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:155-156`、`backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:169-170` → `StateHelper.mergeRevisionNotes`（`backend/src/main/java/com/novel/system/ai/graph/StateHelper.java:75-91`） | 先追加已有意见，再按文本去重，最后只保留最近 `MAX_REVISION_NOTES = 12` 条（`backend/src/main/java/com/novel/system/ai/graph/StateHelper.java:14`） |
| 5. 写作节点消费 | `backend/src/main/java/com/novel/system/ai/graph/WritingNode.java:146-154`、`backend/src/main/java/com/novel/system/ai/graph/WritingNode.java:234-243` | `resolveRevisionNotes` 优先取 `pendingRevisionNotes`、回退到旧的 `draftContent.revisionNotes`；以「=== 待修订问题（请针对性修改，逐条处理）===\n- 逐条」的形式注入写作上下文 |
| 6. 消费一次即失效 | `backend/src/main/java/com/novel/system/ai/graph/WritingNode.java:134-135` | 写作完成后把 `pendingRevisionNotes` 置空，避免下一轮重复注入同一批问题 |

其他意见来源也走同一通道：自审意见（`backend/src/main/java/com/novel/system/ai/graph/SelfReviewNode.java:83-91`）与 deslop 命中项（`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:102-107`）都写进 `pendingRevisionNotes`，所以「门禁 → 自审 → 审校」三层意见在同一处汇合。

**REPLAN 也要回灌**：REPLAN 退回 `outline`，而 `OutlineNode` 只「路过」不消费意见，所以意见必须先落进 state，由后续 `WritingNode` 直接读取（`backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:143-158` 的注释与实现）。

## 7. 事实锁门：降级路径上不可绕过的一致性门

`fact_lock_violation` 检查本章正文是否违反已确立的事实（已故角色复活、时间线倒错、关系违背、世界观硬规则破坏），判据由 LLM 对 `FactLock` 快照做比对（`backend/src/main/java/com/novel/system/service/memory/FactLockServiceImpl.java:157-187`、`backend/src/main/java/com/novel/system/service/memory/FactLockServiceImpl.java:189-229`）。

它之所以是「不可绕过的一致性门」，靠的是三处接线：

1. **正常路径**：`audit_router --PASS--> fact_lock_violation --> summary`（`backend/src/main/java/com/novel/system/service/chapter/MultiAgentNovelService.java:61-63`）；
2. **预算耗尽路径**：`writing` 与 `audit_router` 的重试兜底节点都设为 `fact_lock_violation`，而不是 `summary`——代码注释写明，改兜底的原因是「跳到 summary 会绕过唯一的一致性校验，导致本章被静默强制放行」（`backend/src/main/java/com/novel/system/service/chapter/MultiAgentNovelService.java:73-79`）；
3. **节点本身不吞异常**：`errorStrategy` 为 `SKIP`（失败即跳过本节点继续后续），但内容为空时直接返回、不做误判（`backend/src/main/java/com/novel/system/ai/graph/FactLockViolationNode.java:28-43`）。

命中 `HIGH` 级违规时，节点把违规详情写进 `draftContent.revisionNotes` 并把 `severity` 置 `HIGH`，供后续处理（`backend/src/main/java/com/novel/system/ai/graph/FactLockViolationNode.java:48-66`）；`MEDIUM`/`LOW` 只记录日志，不改稿件（同文件 `backend/src/main/java/com/novel/system/ai/graph/FactLockViolationNode.java:67-71`）。

## 8. 边界：FAST / STREAMING 下不执行什么

拓扑按模式裁剪（`Mode` 三档定义见 `backend/src/main/java/com/novel/system/ai/graph/Mode.java:3-7`），实际生效范围以边声明为准：

| 关口 | FULL | STREAMING | FAST |
| --- | --- | --- | --- |
| `deslop_check` 反 AI 味门禁 | 执行 | 执行 | 执行 |
| `self_review` 自审 | 执行 | 执行 | 执行 |
| `continuity_validation` 跨章连续性 | 执行 | 执行 | **不执行**（节点 `shouldSkip` 判 FAST，`backend/src/main/java/com/novel/system/ai/graph/ContinuityValidationNode.java:30-32`） |
| `validation` 五重并行校验 | 执行 | **不执行** | **不执行** |
| `quality_scoring` 质量评分 + 伏笔落地 | 执行 | **不执行** | **不执行** |
| `audit_router` 七维加权路由 | 执行 | **不执行** | **不执行** |
| `fact_lock_violation` 事实锁 | 执行 | **不执行** | **不执行**（节点 `shouldSkip` 判 FAST，`backend/src/main/java/com/novel/system/ai/graph/FactLockViolationNode.java:22-26`） |

即：STREAMING 走 `writing → deslop_check → self_review → continuity_validation → summary`（`backend/src/main/java/com/novel/system/service/chapter/MultiAgentNovelService.java:55-58`），FAST 走 `writing → deslop_check → self_review → summary`（`backend/src/main/java/com/novel/system/service/chapter/MultiAgentNovelService.java:55`）。**这两种降级模式下既没有加权审校路由，也就没有 REWRITE / REPLAN 决策与审校意见回灌**；能触发的重写只有 deslop 门禁命中（受 `deslop.enforce` 与 `deslop.max-rewrites` 约束）与自审判定 `HIGH`。

其它边界：

- **deslop 门禁可整体关闭**：`deslop.enforce=false` 时命中 `blocking` 也只记录不挡稿（`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:85-91`）；生产配置为 `true`（`backend/src/main/resources/application.yml:123-129`）。
- **重写预算耗尽一律放行**：deslop 预算耗尽决策为 `REWRITE_EXHAUSTED`（继续往下走），审校重写预算耗尽决策为 `MANUAL_REVIEW`（落到兜底节点 `fact_lock_violation`，同样继续往下走），两者语义不同（`backend/src/main/java/com/novel/system/ai/graph/DeslopCheckNode.java:93-100`、`backend/src/main/java/com/novel/system/ai/graph/AuditRouterNode.java:85-94`）。
- **图级上限**：主循环迭代上限 20 步，超出即终止（`backend/src/main/java/com/novel/system/ai/graph/GraphRunner.java:21`、`backend/src/main/java/com/novel/system/ai/graph/GraphRunner.java:86-87`）。
- **本项目不实现的能力**：Provider 自动切换、流式暂停续写、独立轨迹时间线页、按用户配额限流——均不在本章实现范围内，也不在上述门禁链路中出现。
